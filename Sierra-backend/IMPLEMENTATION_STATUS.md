## Default scope
Fiber, Spring Boot, ASP.NET Core and Kafka events are behind `SIERRA_EXPERIMENTAL=1` (`src/engine/experimental.js`); a default install does not list or accept them (`test/default-scope.test.js`). `npm test` sets the flag so their generators stay covered by their tests.


## Express without MongoDB
The node-express flow needs a real MongoDB for its generated tests. When none is reachable, Sierra still generates and delivers all files and reports NOT_VERIFIED with `missingService: MongoDB` (previously an unexplained FAILED). Set `MONGODB_URI` (local mongod or Atlas) to get a VERIFIED run.

## Fields come from your requirement (no LLM needed)
`src/engine/requirementSchema.js` reads `noun (field, field type, ...)` and plain nouns after `API:` from the requirement, so
"Library API: books (title, author, isbn), members, loans" yields Book(title, author, isbn), Member, Loan across all stacks, including Express
(typed Mongoose model, express-validator rules, tests). With an LLM key the LLM designs the schema; if it fails the requirement text is used.
Entities with no listed fields get generic name/description fields, and Sierra says so in the report. Verified: all 8 default stacks VERIFIED via
the API against a Mongo-wire-compatible DB (FerretDB 1.24, not real MongoDB) with this requirement-driven schema; 197/197 tests.

## Only what you ask for
Auth/User, Dockerfile/docker-compose/.dockerignore and the GitHub Actions workflow are generated only when the requirement asks for them
(`src/engine/scope.js`; microservices keep their compose files). "author" no longer triggers auth (whole-word matching). A requirement
that just says `books (title, author, isbn)` yields 14-31 files per stack with no auth, Docker or CI, all VERIFIED here. Express (legacy flow)
only honours the Dockerfile switch; it never generated compose or CI files.
